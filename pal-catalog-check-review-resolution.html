PAL Catalog Check — critical-error resolution

LATEST PRODUCTION FIX LIVE — 22 SEPTEMBER 2026

Reviewer findings addressed

  1. Embedded Admin availability: an earlier review request reached the app while its free Render service was waking and the reviewer saw HTTP 503 / “APPLICATION LOADING”.
  2. Findings CSV export: the reviewer later reported that clicking Findings CSV opened a blank/black page and prevented completion of the export workflow.

Latest Findings CSV remediation

The export flow has been changed so CSV downloads no longer navigate the reviewer or merchant away from the embedded Shopify Admin application.

  1. Removed top-frame export navigation. The Pro dashboard no longer uses direct /app/export?... links or target="_top" for History, Findings, or scheduled-report exports.
  2. Kept the request inside the authenticated embedded route. The UI submits the export request with React Router useFetcher to the authenticated Pro action.
  3. Kept shop isolation on the server. The server obtains the authenticated Shopify session and queries only records belonging to that shop before producing the CSV payload.
  4. Downloads are created in the existing page. The browser receives the prepared CSV payload, creates a local Blob, and triggers the file download without replacing the Shopify Admin view.
  5. Added a recovery path. The page shows success/failure feedback and provides a Download again control if the browser does not begin the automatic download.
  6. Added fail-safe export handling. If the database or CSV preparation fails, the action now returns a warning inside the existing embedded page instead of throwing into an error boundary or replacing the Shopify Admin view.
  7. Added browser-download fallback handling. If the browser blocks the automatic Blob download, the app now keeps the page intact and shows an explicit confirmation warning with a direct Download again control.
  8. Hardened billing lookup failures. If Shopify Partner subscription lookup fails temporarily, the app now falls back safely instead of letting the embedded route crash.
  9. Hardened external support navigation. Privacy/support links now open outside the embedded frame so third-party pages cannot replace the Shopify Admin app surface.
  10. Removed the legacy scheduled-report top-frame export link so there is no second path back into the failed navigation model.

Regression prevention added

  1. A dedicated regression test verifies that Pro CSV exports use the in-page fetcher/download flow and that the old /app/export?... navigation is absent.
  2. A second regression assertion prevents the scheduled-report view from reintroducing top-frame CSV navigation.
  3. Every Render production build now runs the complete test suite and TypeScript typecheck before the production build. A failing test or type error blocks deployment.
  4. The latest production build passed 23/23 tests, TypeScript typecheck, client build, and SSR build.

Additional critical-error hardening

During the final production smoke test we also removed two avoidable public-origin error surfaces before requesting another review:

  1. Standalone app origin: visiting the app origin outside Shopify Admin now renders a clear PAL Catalog Check page explaining that authenticated use happens inside Shopify Admin. It no longer falls into an unauthenticated app error page.
  2. Favicon: /favicon.ico now returns HTTP 200 instead of an incidental 404.

503 / “APPLICATION LOADING” availability remediation

The earlier 503 was traced to the cold-start behavior of the Render Free web-service instance rather than to the catalog workflow itself.

  1. Runtime startup no longer performs Prisma generation or schema synchronization before serving requests.
  2. A lightweight unauthenticated /healthz route returns HTTP 200.
  3. A GitHub Actions availability check requests /healthz every 5 minutes during review to reduce idle spin-down exposure.
  4. No additional Shopify scopes or product/customer/order mutations were introduced by this availability fix.

The app remains on free infrastructure, so the keep-alive measure reduces cold-start exposure but does not change Render's underlying free-service policy.
