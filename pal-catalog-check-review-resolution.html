PAL Catalog Check — 503 / “APPLICATION LOADING” resolution

RESOLVED IN PRODUCTION — 18 SEPTEMBER 2026

Reviewer finding

During Shopify review, the embedded Admin route initially returned HTTP 503 and stayed on “APPLICATION LOADING”. The same transient availability event caused both review findings: no usable merchant UI and a critical web error.

Root cause confirmed

The production app was on a Render Free web-service instance. Render documents that Free web services spin down after 15 minutes without inbound traffic and that the next request can take about a minute while the service starts. The reviewer’s first request arrived during this cold-start window.

Reference: Render Free instance limitations.

Production remediation

  1. Removed database/schema work from runtime startup. Startup no longer runs prisma generate or prisma db push. Those build/setup concerns are kept out of the request-serving path.
  2. Added a lightweight health route: /healthz returns HTTP 200 without Shopify authentication.
  3. Added continuous availability traffic during review: a GitHub Actions availability job requests /healthz every 5 minutes, preventing the 15-minute idle spin-down window while the app remains on free compute.
  4. Preserved the existing embedded merchant workflow. No new Shopify scopes, customer data, order data, product mutations, or merchant-data telemetry were introduced by this fix.
